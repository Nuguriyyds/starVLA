- 1,013,325,887 个有效窗口；窗口在时间上重叠，不能把窗口数当成独立数据小时数。
- 任务表有 99,027 条文本，其中 94,178 个 task ID 在 episode 目录中使用。文本措辞变化不等于新任务类别。
- 所有来源路径均符合本次实际观察到的 `roban_umi/日期/采集标识/领域/场景目录/任务大类/任务目录/文件.mcap` 布局。

- 660 个 task ID 被多个目录组合引用，不能用 task ID 唯一确定场景或目录任务类别。
- 60,352 条 episode 的文本被简单地点短语规则命中，其中 28,600 条提及与目录不同的地点。这是待核对线索，不是已确认的错标或坏数据。

`living_room` 路径组占 71.207% 的 episode 和 66.823% 的有效窗口。两者不同是实际分布差异；本轮没有将任何类别改成等概率。

## 标签的含义

来源目录提供候选任务与场景标签，任务文本提供目标描述。二者都不能替代对真实拍摄环境或实际成功动作的核实。保留原始路径、原文和任务 ID，另存候选分组，禁止覆盖已确认的数据字段。

目录内也可能混有不同目标：例如 `unlace_shoes` 中 episode 75889 的原文为 `Remove the insoles on the balcony`。因此 60 是候选目录组合数，不是已确认的真实任务类别数。人工发现混合类后可以标记“需拆分”，再仅针对该组分析更多文本，不必逐条人工核查全部数据。

地点规则只查找 `in/on/at + 房间名`，不根据台历推断办公室、不根据餐具推断厨房；规则仍可能漏检或遇到歧义。原文中的地点也属于标注，不能当成视频真值。

## 输出与人工参与

`build_umi_semantic_inventory.py` 只读取已有 episode manifest、task catalog、紧凑 ranges 数组及其元信息，不读取 MCAP、图像、视频、逐帧 state/action。

新私人目录 `data_preparation/roban_umi_semantic_review_v1` 保存：

- `inventory.json`：60 组目录统计、每组 3 条固定哈希代表样本及最多 3 条地点措辞差异样本。
- `task_groups.csv`：目录组计数。
- `episode_candidates.csv.gz`：episode 到候选组、原始采集来源、有效窗口数的映射。
- `task_text_candidates.csv.gz`：全任务表原文和实际引用情况。
- `summary.json`：计数和方法范围。

本地人工核查工作簿包含：七个目录场景的含义确认、六十类候选任务名称与技能修订、358 条原文例子。代表样本和差异样本可能重复；示例不是随机频次统计。中文译名、技能标签仍待人工确认。

用户现在核查类别、合并关系及目录场景含义即可，不必逐条审十万条文本。不能确定的场景保留未知。语义标签用于覆盖统计和采样设计，不会重写轨迹的语言指令或动作标签。

确认后再制定多 episode pilot 清单：128 条训练、32 条独立开发验证为候选规模，每条最多 32 个时间分散窗口。先按原始采集来源分训练/验证、排除旧训练来源进入验证，再取窗口和仅用训练数据拟合统计。32 条验证轨迹不能保证覆盖全部 60 类任务，不应宣称逐类全面泛化。
